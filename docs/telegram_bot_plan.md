# Телеграм-бот: канал доставки алертов и сигналов

Статус: реализовано (переделка 2026-08-14). Бот `@deskdeskdesk_bot` больше не
имеет своей настройки: Mini App и собственный скринер удалены, всё заводится на
сайте, бот лишь дублирует события в привязанный чат.

## Идентичность

Ключ владельца везде — **email веб-аккаунта**. Телеграм-чат к нему привязывается:

```
/start (или любое сообщение) ──▶ tg_users: строка status='pending', email=NULL
                                          ↓
   админ на сайте: Настройки доступа → Телеграм → выбрать аккаунт → «Одобрить»
                                          ↓
                     status='approved', email=<аккаунт>  →  доставка пошла
```

Пароли в чат не вводятся. Неодобренный чат получает только ответ «заявка
принята» со своим ником/ID — админ по ним находит строку в админке.
При одобрении алерты легаси-идентичности `tg:<id>` (автономный бот до
переделки) переезжают на email владельца — иначе осиротели бы молча.

Один аккаунт может иметь несколько чатов (телефон + десктоп): доставка идёт во
все approved и не-muted.

## Доставка

| Источник | Врезка | Как уходит |
|---|---|---|
| Алерты по стакану (`alerts`) | `alerts_monitor` → `tg_notify.enqueue` | сразу: PNG стакана (Pillow) + подпись |
| Сигналы вкладки СИГНАЛЫ (`signals.run_cycle`) | рядом с WS-пушем → `enqueue_signal` | буфер, пачкой раз в `TG_SIGNAL_FLUSH_SEC` (30 с) |
| Крупные сделки (`block_trades.notify_blocks`) | там же | тот же буфер, `kind='block'` |

Буфер нужен, потому что такт скринера секундный: поштучная отправка выбила бы
лимиты Bot API и превратила чат в ленту. В сообщении не больше 8 бумаг, хвост
сворачивается в «…ещё N».

## Команды бота

Только чтение и пауза: `/alerts`, `/signals`, `/mute`, `/unmute`, `/status`,
`/help`. Создание и правка — на сайте.

## Файлы

* `services/telegram.py` — httpx-клиент Bot API (ретраи 429/5xx).
* `services/tg_users.py` — привязка чатов: `request_access`, `approve`, `revoke`,
  `chats_for_email`, `has_chats`, `set_muted`.
* `services/tg_notify.py` — очередь алертов (`tg_notify_worker`) и буфер
  сигналов (`tg_signal_worker`).
* `services/tg_render.py` — PNG стакана с per-level Y-IDX/DM (эмодзи не рисовать:
  тофу в DejaVu).
* `api/routes/tg.py` — вебхук (secret-заголовок) + `/api/tg/links*` под
  `require_admin`.
* `frontend-react/src/components/AdminPanel.jsx` — секция «Телеграм».

## Эксплуатация

1. В прод-`.env`: `TG_BOT_TOKEN`, `TG_WEBHOOK_SECRET`, `TG_WEBHOOK_URL`.
2. `python scripts/tg_set_webhook.py` — регистрирует вебхук, возвращает
   меню-кнопку к списку команд (Mini App снесён) и ставит `setMyCommands`.
3. Пользователь пишет боту `/start`, админ одобряет заявку на сайте.

**Каветат прода**: `api.telegram.org` с VPS reg.ru доступен только по IP из
`extra_hosts` (`TG_API_IP`, рабочий 149.154.167.220) — DNS хостера отдаёт лишь
AAAA, IPv6-маршрута нет. Замолчал бот — сначала `curl --resolve` с VPS.
