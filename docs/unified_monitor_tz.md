# Единый монитор облигаций (флоатеры + фиксы) — ТЗ

Согласовано 2026-10-06. Цель: все бумаги в одной витрине, один вотчлист, одна карточка по клику.

## Решения

1. **Спред — Y-IDX у ВСЕХ** (уточнено 2026-10-06, заменяет вариант «родной спред + Z»).
   Фиксам считаем Y-IDX нашей моделью: `ytm − ruonia_rolling_yield_pct(ruonia_curve, calc_date,
   горизонт)`. База та же, что у флоатеров (роллирование RUONIA ≈ OIS), поэтому колонка SPREAD
   и сортировка по ней честные для смеси классов. У фикса это по смыслу asset-swap-спред к RUONIA;
   у ОФЗ — базис ОФЗ–OIS (может быть отрицательным).
   - Конвенции совместимы: YTM фикса — тот же `core.valuation.xirr` (эффективная годовая,
     ACT/365), base leg приведён к той же аннуализации и якорю T+1.
   - Base leg от цены не зависит → стороны дёшевы: `y_idx_bid = ytm_bid − base`, то же ask/wap/
     объём. Base leg на бумагу кэшировать на день (+ отпечаток RUONIA-кривой).
   - Горизонт — правило прайсинга фиксов (пут/продление неопределённого купона до выкупа MOEX).
     Бессрочные — Y-IDX нет (горизонта нет), прочерк.
   - Y-IDX показывать и в карточке фикса.
   - G-спред и Z КБД остаются колонками по выбору (не в дефолтном наборе).
2. **Класс** — через существующий фильтр БАЗА: KEYRATE / RUONIA / **FIXED** (как в сигналах).
   По умолчанию — все.
3. **Меню** — один раздел «Облигации»: Монитор, Сравнение, Сделки, Сигналы, Выплаты, Первичка,
   ОФЗ, Аукцион, Калькулятор. `/fixed` → редирект на монитор с `base=FIXED`.
4. **Первый шаг** — монитор + карточка + вотчлист (+ EMITTER_ID фиксам). Аналитика, Сравнение,
   Выплаты — второй шаг.
5. **Различимость классов** (2026-10-06):
   - строка: цветная полоска слева (новые токены `--cls-float`/`--cls-fixed` в 4 темах — не
     совпадать с `--up`/`--down` и `--accent`) + бейдж базы КС / RU / ФИКС;
   - буквы Y/G у чисел НЕ ставим;
   - под ценой BID/ASK/СР.ВЗВЕС: у флоатера Y-IDX стороны, у фикса **YTM стороны, как сейчас**
     (различимо форматом: бп vs %);
   - неприменимая к классу колонка — пустая ячейка; прочерк = «должно быть, но нет данных»;
     пометка класса в заголовке; колонка класса, убранного фильтром, скрывается сама (без правки
     сохранённой раскладки); меню колонок — группы общие / флоатеры / фиксы;
   - YTM флоатера — курсивом, подсказка «модельная: форвард индекса»;
   - DUR — чувствительность к 1 бп спреда у обоих: фикс `mod_dur`, флоатер `spread_dur_yrs`
     перевести из Маколея в модифицированную (иначе расхождение 3–7 %);
   - DIRTY всегда с валютой; КУПОН одной колонкой (формула флоатера / ставка фикса);
   - KPI: медиана Y-IDX — общая (база одна), плюс счётчики ФЛТ/ФИКС.

## Решения 2026-10-14

- **Структурные ноты** — флаг `structured` (купон ≤ 1 %, кроме ОФЗ) у строки фикса; в общем
  мониторе фильтр «без структурных» включён по умолчанию. Биржевого признака нет: MOEX пишет
  СберИОС «облигацией с фиксированным купоном». На TQCB 572 бумаги с купоном ≤ 1 %: СберИОС,
  ВТБС, СберСIB/CIB, ГПБ…P, Альфа, Совком; в ту же корзину честно попадают глубокий дисконт
  (Пересвет) и младшие транши СФО — их YTM-спред тоже не про рынок ставок.
- **Размер витрины** (~640 флоатеров + до 1500 фиксов) — фильтр фиксов по ликвидности (ADV)
  по умолчанию; виртуализация таблицы — если замер B8 покажет, что тормозит.
- **ОТКЛ 7Д у фиксов** — пустая до бэкфилла Y-IDX (этап C): база недели у фиксов в барах —
  G-спред, сравнивать её с живым Y-IDX нельзя.
- **DUR флоатера в модифицированную** — отложено.
- **BID/ASK фикса** — под ценой Y-IDX стороны, третьей строкой YTM к той же цене (заменяет
  «YTM стороны, как сейчас» из решения 5). Фильтр по объёму подменяет оба числа на числа
  цены набора (`FIXED_VOL_FIELDS.bidSpread2`).
- **Деплой** — только из чистого рабочего дерева (`scripts/deploy.sh` отказывает).

## Что уже общее (не трогаем)

- Один WS `/api/ws/market`, один стрим Alor, один движок (`universe_stream`); ценовые патчи
  одной формы для обоих классов.
- Универсы не пересекаются по построению: `fetch_fixed_universe` выкидывает
  `reg.non_fixed_isins()`; на TQOB только SU25/SU26 (ОФЗ-ПК SU29 и линкеры SU52 — не фиксы).
- `BondTable`/`Toolbar`/`FiltersMenu` параметризованы; `Drawer` выбирает `FixedCard` по `?k=fixed`.

## Этап A — контракт на бэке

- **A0. Y-IDX фиксам.** В `fixed_metrics_from_schedule` / движке фиксов (`_crunch_fixed`,
  `_recrunch_fixed_sides`) — `y_idx_bps`, `y_idx_bid/ask/wap_bps`, объём; прокинуть
  `ruonia_curve` во все точки расчёта фиксов (иначе тихий None). Поля — те же имена, что у
  флоатеров (`yield_over_index_bps`, `y_idx_*`), в WS-патч, котировки, `/api/fixed/{isin}`.
  **СДЕЛАНО 2026-10-06** (не закоммичено): `fixed_income` (`ru_curve` во всех точках расчёта,
  база до конца потока, прочерк у валютных/бессрочных/линкеров), движок (`_crunch_fixed`,
  `_recrunch_fixed_sides`, `_fixed_vol_maps`), WS-патч, `/api/fixed` (+котировки `vol_*_y`),
  карточка и калькулятор, уровни стакана фикса (`y_idx_bps`), колонка SPREAD и плитка в
  карточке на фронте. Тесты: `tests/test_fixed_yidx.py`, `mergeRules.test.jsx`. Прод-замер
  на живых данных: Y-IDX есть у 588/731 фиксов; ОФЗ от −278 (короткие, низкокупонные) до +108.
  **История — решение (а):** графики фиксов остаются на G (SpreadHistory key `g_spread_bps`),
  Y-IDX копится вперёд в `spread_daily.y_idx` (kind=fixed) с 06.10; `bars` для фиксов по-прежнему
  пишут G. Бэкфилл Y-IDX по архивной RUONIA-кривой — этап C (архив своп-котировок с 30.07).
  Блок-фильтры сигналов (`y_idx_bps` сделки) по фиксам пока не работают — тоже этап C.
  Нельзя молча смешать G (история) и Y-IDX (живое) на одном графике.
  **Ловушка для общей сортировки:** структурные ноты (СберИОС, ГПБ0xxР…) в универсе фиксов дают
  YTM/спреды в минус тысячи бп — решить в этапе B (флаг/фильтр), иначе забьют верх сортировки.
- **A1. `kind`** (`"floater"` | `"fixed"`) в строке списка, в элементе котировок и в WS-патче
  метрик (`_metrics_patch` / `_fixed_patch`, сейчас фронт фиксов различает патчи по членству
  ISIN в своём наборе). **СДЕЛАНО 2026-10-13.** В котировках `kind` только у бумаг движка
  (флоатер — есть в `universe_metrics`, фикс — в `fixed_metrics`); остальной рынок без него.
- **A2. Общие имена для общих понятий** в строке фикса:
  `name→short_name`, `issuer→emitter_name` (+`emitter_id`), `bid/ask→bid_price_pct/ask_price_pct`,
  `wap_pct→wap_price_pct`, `ytm→yield_xirr_pct`, `coupon_pct→current_coupon_pct`,
  `put_date→offer_date/offer_kind`, `cls→is_ofz`. Специфичное остаётся своим
  (`g_spread*`, `z_spread_bps`, `ytm_bid/ask/wap`, `mod_dur`, `convexity`, `dv01`, `cur_yield`,
  `delta_ytm`, `face_unit`, `perpetual`). **`dirty` ≠ `dirty_price_rub`**: у фикса — в валюте
  номинала, у флоатера — в рублях; не сливать.
- **A3. Один список:** `/api/bonds?universe=1&kinds=floater,fixed` (фиксы из
  `fixed_universe` + `fixed_metrics` через адаптер), `vol_bid/vol_ask` для обоих.
  **СДЕЛАНО 2026-10-13:** `kinds` по умолчанию `floater` (старый ответ не меняется); строки
  фиксов строит та же `api/routes/fixed.fixed_rows`, адаптер `bonds._fixed_list_item`
  переименовывает общие понятия из A2 (`_FIXED_RENAME`), специфичное едет своими именами
  через `BondListItem` с `extra="allow"`; `limit` до 5000. A2 этим закрыт только для
  общего списка — `/api/fixed` отдаёт прежние имена до перехода фронта.
- **A4. Котировки:** фиксы в дельта-журнал `/api/bonds/quotes` (`since/epoch`) — он и так
  обходит весь снапшот борда, не хватает метрик фиксов (g/YTM сторон, средневзвес через
  `fixed_income.pick_wap`). Правило: каждое число едет рядом с ценой, к которой посчитано.
  `/api/fixed/quotes` — удалить после перехода фронта.
  **СДЕЛАНО 2026-10-13** (`bonds._fixed_quote`): у фикса `wap` по `pick_wap`, стороны из
  движка по наличию ключа, группы «цена расчёта → числа»: `yoi_px`→`yoi/ytm/g`,
  `yoi_wap_px`→`yoi_wap/ytm_wap/g_wap`, `yoi_bid_px`/`yoi_ask_px`→`yoi_*/ytm_*/g_*`;
  цена набора — плоско `vol_{side}_{px,g,ytm,y}`. Тесты: `tests/test_unified_list.py`.
- **A5. EMITTER_ID фиксам.** Сейчас эмитент фикса — регэксп по имени (`_issuer_of`), у флоатера —
  MOEX EMITTER_ID реестра. Без этого фильтр «все бумаги эмитента» расколется на два имени.
  Разовый добор по ISS (~700 запросов), кэш навсегда; ОФЗ → синтетический `-1` (как в реестре);
  фолбэк — регэксп.
  **СДЕЛАНО 2026-10-14** (`services/emitters.py`): не по бумаге, а списком ISS
  `/securities.json?engine=stock&market=bonds` — ≈32 страницы на весь рынок (3178 бумаг, все с
  `emitent_id`), durable `data/cache/emitters.json`, пересбор раз в сутки или на свежий выпуск
  (не чаще 6 ч), куцый ответ карту не затирает. Имя — реестра по тому же id (там короткое),
  иначе прежнее из имени выпуска. Вызывается из `fetch_fixed_universe`.
- **A6. Рейтинг.** У флоатера сырое значение реестра, у фикса бакет (`bucket_map_fixed`,
  ОФЗ=AAA). Проверить `ratingMatches` на обоих видах значений.
  **СДЕЛАНО 2026-10-14:** фикс получает ступень худшего рейтинга из слоя bondresearch
  (`ratings_br`, тот же вид, что у флоатеров), грейд — фолбэком, ОФЗ — AAA. `ratingMatches`
  понимает оба вида: чип режет по грейду, меню ступеней — по точному значению.

## Этап B — фронт

- **B1.** `Dashboard` грузит общий список. Логика слияния живых данных — одна (флоатерный путь
  `mergeStreamedQuote`, расширенный на поля фиксов). `FixedMonitor` (`applyPatch`/`mergeLive`)
  удалить, правила из `mergeRules.test.jsx` перенести на общий путь — в них зашиты уроки
  2026-09-22 (частичный патч не стирает строку; гасится только сдвинувшаяся цена).
- **B2. Колонки** — объединение наборов (см. решение 5). SPREAD = `yield_over_index_bps` у обоих
  классов, сортировка общая. Под ценой — по `row.kind` (Y-IDX / YTM). G-спред, Z КБД, CONV, DV01 —
  колонки по выбору.
- **B3. Фильтры:** БАЗА + FIXED; окно спреда — по родному спреду; окно YTM и валюта (сейчас у
  фиксов) — общие; «без неторгуемых» — для обоих.
- **B4. KPI в статус-баре** — MED Y-IDX общий, счётчики ФЛТ/ФИКС.
- **B5. Карточка:** `onOpen(isin, el, row.kind)` вместо `rowKind` на всю таблицу.
- **B6. Состояние:** вотчлист `watch ∪ watch_fx` (разовая миграция); раскладка колонок — новый
  ключ; URL-ключи `fx*` → маппинг на общие при редиректе с `/fixed`.
- **B7. Меню:** `Topbar.TYPES` floaters+fixed → «Облигации», `SUBNAV` объединить,
  `/fixed` → `Navigate`; `/fixed/ofz`, `/fixed/auction` — пути не меняются.
- **B8. Производительность:** ~1370 строк без виртуализации. Замерить первый рендер и тики;
  виртуализация — только если тормозит.
