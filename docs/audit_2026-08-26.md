## CRITICAL

### 1. `services/alor_ws.py:302` — живой WS-сокет падает на каждой сделке
`_tick_value()` с коммита 8389fca возвращает `tuple[float, bool]`, а вызов передаёт его
как `value=`. В `live_quotes._DayVwap.add` строка `self.val += float(value)` → TypeError.
Кортеж всегда truthy, срабатывает на КАЖДОЙ сделке подписанной бумаги. Исключение ловится
общим `except Exception` в `alor_ws.py:320` → реконнект сокета на каждом тике.
Побочно: `num`/`den` уже инкрементированы, `n` — нет, дневной агрегат портится молча.

Фикс: `val, _fx_ok = _tick_value(...)` и передавать `value=val`.

### 2. `services/instruments_registry.py:31` — `face_value` заморожен как «ручной параметр»
`face_value ∈ _MANUAL_FIELDS`, хотя это функция времени. Дневной синк из листинга MOEX
его не трогает на locked-строке. В БД: 55 активных locked-строк с `face_value < 1000`,
из них 23 ипотечных агента заморожены на 2026-07-29. Guard `bonds.py:200`
(`whole < current_face*0.95 → None`) на МБС не спасает — MOEX публикует только объявленные
транши. Цена в % от неверного номинала → dirty/Y-IDX/SM врут пропорционально.

Фикс: убрать `face_value` из `_MANUAL_FIELDS`; остаток номинала — только из листинга/амортизаций.
